PTX vs SASS

PTX 是地图，SASS 是地形

PTX 暴露编译器的意图；SASS 确认 GPU 最终实际执行的指令序列。

当你需要可读的 lowering 结构时，读 PTX

ld.global.v4.u32 // 向量宽度与内存空间
st.local.u64 // local memory 流量
mma.sync // tensor-core 意图
bar.sync // 同步形态

适合用于

源码映射、内存空间确认、寄存器声明、广泛的模式检测，以及可读的结构证据。

需要注意

PTX 不是最终的调度、不是最终的寄存器分配、也不是最终的目标指令选择。

当你需要知道 GPU 实际跑了什么时，读 SASS

HGMMA.MMA // Hopper tensor 路径
UTMALDG // TMA 批量传输
STL / LDL // 机器路径中的 local store/load
ARRIVES // 异步协调

适合用于

原生 opcode、目标架构特定行为、真实的机器指令词汇、架构漂移检测。

需要注意

更难阅读、架构强相关、文档不完整，且仍然不能替代 profiling。

关联层 — PTX 与 SASS 的交叉验证
PTX 中的 mma.sync 对应 SASS 中的 HMMA，说明后端兑现了 tensor-core 意图。
PTX 中的 st.local 对应 SASS 中的 STL/LDL，说明 local memory 流量存活到了机器路径中。
PTX 中的警告如果没有 SASS 的确认，只是假设；PTX + SASS 联合验证才是更强的执行结构发现。
