关键观察

为什么是"硬连线"？

从 Thread 5 的寄存器分配可以看出这些规律：

行由 T/4 决定。 Thread 5 的 groupID = 1，所以它永远负责第 1 行和第 9 行（1 + 8）。不管你怎么排数据，硬件就是从这个线程的寄存器读这两行的元素。

列由 T%4 决定。 Thread 5 的 threadInGroup = 1，所以它覆盖第 2、3 列（以及 A 矩阵的第 10、11 列）。每个寄存器装 2 个相邻的 f16。

上下半矩阵用不同寄存器。 行 0-7 在 R0/R1，行 8-15 在 R2/R3。Tensor Core 通过切换读取的寄存器编号来访问矩阵的上半部分和下半部分。

总结

ldmatrix 做的事 = 把 shared memory 的数据搬到这张图的正确位置

上面的可视化展示了 MMA 指令期望数据在寄存器里的位置。ldmatrix 的工作就是：从 shared memory 读取矩阵数据，然后在一条指令内把每个元素分发到对应线程的对应寄存器——也就是上图中每个格子标注的位置。

如果没有 ldmatrix，你需要用 ld.shared（每个线程各自加载）+ shfl.sync（线程间交换数据）手动实现同样的分发，既慢又容易放错位置。

这就是为什么说寄存器布局是"硬连线"的：不是你选择把数据放在哪个线程的哪个寄存器，而是硬件规定了它从哪里读。你的工作是把数据送到那里。
