正在发生什么

GPU Mode 排行榜、KernelBench、KernelAgent、K-Search、TritonBench 式任务，以及更新的 KernelBench 变体，正在把 kernel 编写变成一个搜索-评估循环。

为什么仅靠计时不够

生成的代码可以通过测试并且看起来很快，但实际上在利用 harness 漏洞、跳过计算、没命中 tensor core、标量化搬运，或者严重 spill。

解析层

我们将 PTX/SASS 解析为结构化的指令、操作数、地址空间、寄存器、属性和源码位置，然后再做模式检测。这使得分析结果可 diff。

检查器检查什么

应检查生成的路径是否包含：架构原生指令、正确的内存宽度、local traffic、barrier 结构，以及明显的回退行为。

四阶段流水线是对前几张 slide 的系统化总结

前面的 slide 分别讲了：AI kernel 会语义作弊（→ 需要正确性隔离）、会 benchmark gaming（→ 需要 benchmark 隔离）、会走差的硬件路径（→ 需要 PTX/SASS 审查）、profiler 能量化最终效果（→ 需要 profiler 验证）。这张 slide 把这四个散落的观点编排成了一条完整的验证流水线。

关键是顺序：先确保答案对（阶段 1），再确保没作弊（阶段 2），然后确保硬件路径对（阶段 3），最后用 profiler 量化确认（阶段 4）。跳过任何一层都留下盲区。

"编译产物检查器"的定位：不判对错，判路径

传统的测试只验证数值正确性——输出对不对。编译产物检查器做的是结构审查：不是判断"答案对不对"，而是判断"生成的硬件路径好不好"——有没有命中原生指令、内存宽度对不对、有没有意外 spill。

这和前面 NCU vs PTX/SASS 那张 slide 的观点一致：NCU 测量运行时效果，编译产物检查器审查编译结构。两者结合才构成完整的质量判断。

"Slop Kernel" 是这张 slide 引入的核心概念

"Slop"（低质量内容）这个词从 AI 生成文本领域借来，用在 kernel 上特别贴切：correct but ungrounded——答案对了，但没有硬件层面的依据。它可能恰好在这组输入上快，换个输入大小就慢了；它可能用了标量搬运凑巧没被内存带宽限住；它可能 spill 了但 L1 命中率够高所以没暴露问题。

没有经过编译产物审查的 kernel，你无法区分"真的好"和"凑巧好"。这就是 slop kernel 的危险——它能通过所有传统测试，但在生产环境、大规模输入、不同硬件上可能直接崩溃。

"可 diff"的分析是工程化的关键

Parser layer 那段提到"将 PTX/SASS 解析为结构化数据，使分析可 diff"。这个细节很重要：如果检查器的输出是人类可读的文本报告，那它就不能嵌入自动化流水线。但如果是结构化的、可 diff 的数据（指令列表、地址空间标注、寄存器使用统计），那它就可以：

1. 和上一版本的编译产物做 diff，看改动有没有引入回退。
2. 在 CI 里设门禁：出现 st.local 就拒绝合并。
3. 作为 agent 搜索循环的一部分，自动淘汰结构不合格的候选 kernel。

四层防线各自的盲区——为什么缺一不可

验证阶段能抓到什么抓不到什么典型工具
1. 正确性隔离 错误结果、return 0 式作弊 答案对但路径差的 kernel 参考实现对比、随机输入、shape 覆盖
2. Benchmark 隔离 计时器 monkey-patch、harness 利用 合法但低效的执行路径 子进程隔离、计时完整性校验
3. 编译产物检查器 非原生指令、spill、标量搬运、回退路径 静态结构无法证明运行时开销 PTX/SASS 解析器、模式匹配、diff
4. Profiler 验证 实际的 stall、带宽、tensor 利用率 不知道"预期"是什么，无法判断回退 Nsight Compute、microbench、硬件计数器

底部的流水线图是这张 slide 的核心画面：benchmark 喂给 agent/search loop，agent 生成候选 kernel，编译产物检查器作为分流器——合格的成为 hardware-grounded kernel（经过测量 + 结构验证），不合格的被标记为 slop kernel（正确但无硬件依据）。这条流水线的价值在于：slop kernel 在到达 profiler 之前就被拦截了，节省了大量无效的 profiling 时间。

这也回应了整个 slide deck 的主线：在 AI 生成 kernel 的时代，"搜索-评估循环"中缺少结构审查这一环，就等于在用一半的标准筛选候选方案。加入编译产物检查器后，搜索空间的质量才是完整可控的。
