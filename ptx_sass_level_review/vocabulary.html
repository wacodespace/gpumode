读懂分析结果所需的最小词汇表

分支 / 谓词

分支形态是编译器生成的结构

源码中的 if 可能变为谓词执行、分支跳转、reconvergence 或 uniform control。分歧（divergence）是一个硬件执行层面的问题。

setp.ne.s32 %p0, %r1, 0;
@!p0 bra target;

溢出将寄存器压力变为内存流量

.local 是线程私有的地址空间，但 spill/reload 流量本质上是一条会在运行时产生开销的内存路径。

ld.local.u64 %rd120, [%rd2];

深入：PTX 中的三种条件执行机制

Predicate（谓词）

不跳转，两边都执行，用掩码选结果

两条指令都会发射，被"掩掉"的那条不写回结果。没有分支跳转，没有 warp 分裂的风险。适合两个分支都很短（一两条指令）的情况。

setp.gt.f32 %p1, %f1, %f2;
@%p1  add.f32 %f3, %f1, 1.0;
@!%p1 add.f32 %f3, %f2, 1.0;

Branch（分支跳转）

真正的控制流跳转

如果 warp 内 32 个线程走了不同方向则 diverge，两条路径串行执行。适合分支体较长、用 predicate 全执行代价太大的情况。

setp.ne.s32 %p0, %r1, 0;
@!p0 bra ELSE_LABEL;
// then 代码 ...
bra END_LABEL;
// else 代码 ...

Uniform Control（统一控制流）

编译器能证明 warp 内所有线程走同一边

条件在 warp 内一定一致（如基于 blockIdx 的判断）。硬件可优化：不需要保存 reconvergence 点，不需要两条路径都跑。

// uniform predicate
@%up0 bra TARGET;
编译器的选择逻辑：源码 if (cond) { A } else { B } → 分支体很短 → Predicate（两边都执行，掩码选）｜ 分支体较长 → Branch（跳转，可能 diverge）｜ 编译器能证明 warp 内一致 → Uniform（无 divergence 风险）

Divergence 是硬件执行层的问题，不是编译层的问题

源码层根本判断不了是否会 diverge，因为它取决于运行时每个线程的数据值。同一段 if (x[threadIdx.x] > 0)，一个 warp 内 32 个线程的 x 全 > 0 就不 diverge；16 个 > 0、16 个 ≤ 0 就 diverge。同一份代码，换一批输入数据，行为完全不同。

PTX 能告诉你"编译器给了 diverge 的可能性"（用了 branch 而不是 uniform），但"是否真的发生了"只有硬件在运行时才知道。最终由 Nsight profiler 报告实际的 divergent branch 次数。
