Multimem

NVIDIA 硬件级多卡归约指令集

一条指令，多卡读取 + 归约

Multimem（Multi-Memory Access）是 NVIDIA 从 Hopper (H100) 架构开始引入的一组硬件级内存指令。
核心能力：一条 PTX 指令同时对多个 GPU 的内存地址执行读取 + 归约（reduce），或写入 + 广播。

关键 PTX 指令

指令 作用
multimem.ld_reduce 从多块 GPU 的内存中加载数据，硬件自动执行 reduce（如 sum / max），一条指令完成
multimem.st 向多块 GPU 的内存同时写入数据（类似广播）
multimem.red 对多块 GPU 内存执行原子归约操作
  • 这些指令在 PTX ISA 层面定义，由 NVSwitch / NVLink 硬件直接执行归约逻辑
  • 支持的归约操作包括：ADD、MIN、MAX 等
  • 支持的数据类型：FP16、BF16、FP32、INT32 等

为什么重要：传统方式 vs Multimem

传统 AllReduce

  1. GPU A 把数据拷贝到 GPU B 的显存
  2. GPU B 启动 CUDA kernel 做加法
  3. 将结果再拷贝到其他 GPU
  4. 多次数据搬运 + 多次 kernel launch

Multimem AllReduce

  1. 调用 multimem.ld_reduce 一条指令
  2. NVSwitch 硬件直接完成 reduce
  3. 结果直接写回，无需中间搬运
  4. 一条指令 = 读 + 归约，延迟大幅降低
  • 数据无需先落到某块 GPU 显存再计算 — 硬件在 NVSwitch / NVLink 层面直接完成 reduce
  • 减少 kernel launch 开销 — 不再需要多个 kernel 来搬运和计算
  • 降低显存带宽压力 — 数据在互联网络上完成归约，不占用 HBM 带宽

与 NVLS 的关系

  • Multimem 是底层硬件指令，NVLS（NVLink SHARP）是 NCCL 中基于 Multimem 实现的通信协议
  • 当 NCCL 检测到硬件支持 Multimem（Hopper+ 架构 + NVSwitch 拓扑），会自动选用 NVLS 通道
  • NVLS 底层调用 multimem.ld_reduce / multimem.st 来加速 AllReduce、ReduceScatter 等集合操作
  • 这就是 Hopper 架构 AllReduce 性能大幅领先上一代的关键原因之一

在 NCCL 集成栈中的位置

用户脚本 (User Script)
框架层 (vLLM / PyTorch + Custom Kernels)
NCCL Device APIs
NVLink / NVSwitch — Multimem 指令在此执行
← multimem.ld_reduce / multimem.st / multimem.red
  • Multimem 指令工作在 NVLink / NVSwitch 传输层，属于 LSA（本地系统架构）范畴
  • 上层的 NCCL Device APIs 通过 NVLS 协议间接调用这些指令
  • 用户无需手动调用 — NCCL 根据硬件拓扑自动选择是否启用

硬件要求

  • GPU 架构 — Hopper (H100) 及以上，即 SM90+
  • 互联 — 需要 NVSwitch 连接的 NVLink 拓扑（如 DGX H100 / HGX H100）
  • 驱动 & CUDA — 需要 CUDA 12.0+ 及对应驱动版本
  • NCCL 版本 — NCCL 2.17+ 开始支持 NVLS / Multimem 路径
Multimem = GPU 硬件原生支持的"一次读多卡 + 顺便做 reduce"指令集，
让 NVLink 上的集合通信从"软件搬数据 → 算 → 再搬"变成"硬件一条指令搞定"。
