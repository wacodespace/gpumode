内容总结

  • NCCL Device API 是一套"内核通信工具箱"，允许用户在 GPU 内核中直接调用通信原语，而无需回到主机端。
  • 主机端需要准备两个对象：Device Communicator（通过 ncclDevCommCreate 创建，等价于主机端的 comm，代表一组 rank）和 Window（通过 ncclCommWindowRegister 创建，代表跨 rank 注册的共享内存缓冲区）。
  • 这两个对象被传递到 GPU 内核中，供设备端 API 使用。
  • 设备端提供三类通信原语：
    • LSA — 用于可直接 load/store 访问的内存（如 NVLink 可达的对端 GPU 显存）的通信操作。
    • Multimem — 利用 NVLink SHARP（硬件加速的归约能力）执行通信操作。
    • GIN — GPU-Initiated Networking，让 GPU 线程直接发起网络通信（如 InfiniBand RDMA），无需 CPU 介入。
  • 核心价值：将通信控制权从主机下放到 GPU 内核，使开发者能够在自定义 kernel 中灵活嵌入通信逻辑，实现计算与通信的细粒度重叠，减少内核启动开销和主机同步延迟。
  • 根本目的 — 降低开发难度：在没有 Device API 之前，想在自定义 kernel 中做多卡通信，开发者必须自己处理底层细节 — 手动管理 NVLink 地址映射、编写 Multimem PTX 内联汇编、实现 GIN 网络协议栈。Device API 把这些复杂度全部封装为三组简洁的 C 函数调用（LSA / Multimem / GIN），开发者只需关心"把什么数据发给谁"，不需要知道底层走的是 NVLink 还是 InfiniBand，也不需要手写 PTX 指令。这就像从手写汇编跳到调用库函数 — 功能一样，但开发门槛天差地别。
