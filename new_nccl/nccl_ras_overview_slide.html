RAS 概览

  • RAS Thread + RAS Client 双组件架构
  • RAS Client 支持监控模式（monitor mode）和查询模式（query mode）
  • 开销极小（Minimal overhead）
  • 提供 RAS API 供用户接入自有可观测性体系 路线图

内容总结

  • RAS（Reliability, Availability, Serviceability）是 NCCL 内建的可靠性监控子系统，旨在帮助大规模 GPU 集群及时发现和诊断通信故障。
  • 双组件架构：
    • RAS Thread — 嵌入在每个 NCCL 进程内部的轻量线程，负责收集本地通信状态和异常信息，并通过 RAS 网络与其他节点的 RAS Thread 交换健康状态。
    • RAS Client — 外部客户端工具，可连接到任意 NCCL 进程的 RAS Thread 来获取集群级别的通信健康视图。
  • RAS Client 的两种模式：
    • 监控模式（Monitor Mode） — 持续订阅并实时接收异常事件推送，适合长期运行的监控场景。
    • 查询模式（Query Mode） — 按需查询当前集群通信状态的快照，适合故障排查和诊断。
  • 开销极小：RAS Thread 被设计为几乎不影响正常通信性能，在后台轻量运行。
  • RAS API（路线图）：未来将开放 RAS API，允许用户将 NCCL 的健康数据接入自有的可观测性体系（如 Prometheus、Grafana 等），实现统一监控。
  • RAS 网络：RAS Thread 之间通过独立的 RAS 网络互联（如图中虚线所示），形成全连接的健康检查网格，可以检测到跨节点的通信异常。
