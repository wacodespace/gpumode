内容总结

一、整体架构概述

  • 本 slide 展示了 NCCL 自定义通信内核 (Custom Communication Kernels) 在整个软件栈中的位置和集成方式。
  • 架构共分 四层：用户脚本层 → 框架 + 自定义内核层 → NCCL 设备 API 层 → 硬件传输层。

二、各层详解

  • 用户脚本 (User Script) — 最上层，是用户编写的训练或推理脚本，负责调用下层框架。
  • 框架 + 自定义内核 — 用户可以通过 vLLM 或 PyTorch 两大框架接入，同时在其旁边插入自定义通信内核来替换或增强默认的集合通信实现。
  • NCCL Device APIs — 自定义内核与框架统一通过 NCCL 设备 API 进行通信，这是整个栈的核心抽象层，提供统一的设备端接口。
  • 硬件传输层 — NCCL 设备 API 向下适配四种物理传输方式：
    • • IB/RoCE — InfiniBand / RDMA over Converged Ethernet，用于跨节点高速网络通信
    • • EFA — Elastic Fabric Adapter，AWS 提供的弹性高性能网络适配器
    • • NVLink — NVIDIA 专有的 GPU 间高速直连互联
    • • PCI — PCI Express 总线，最基础的设备互联方式

三、GIN 与 LSA 分类

  • GIN (Global Interconnect Network) — 跨节点互联网络，涵盖 IB/RoCE 和 EFA，用于多机之间的通信。
  • LSA (Local System Architecture) — 本地系统架构，涵盖 NVLink 和 PCI，用于单机内 GPU 间及 GPU 与 CPU 之间的通信。

四、核心要点

  • 可插拔设计 — 自定义内核 (Custom Kernels) 可以与 vLLM / PyTorch 并行集成，允许用户编写自己的高性能通信算法并无缝接入现有框架。
  • 统一抽象 — 所有通信路径最终汇聚到 NCCL Device APIs，无论底层使用何种传输方式，上层接口保持一致。
  • 全栈覆盖 — 从用户脚本到物理传输，支持跨节点 (GIN) 和节点内 (LSA) 两种场景，覆盖主流的 GPU 集群互联拓扑。
  • 灵活适配 — 用户可根据集群硬件配置（InfiniBand / EFA / NVLink / PCIe）选择最优传输路径，NCCL 会自动路由到对应后端。
