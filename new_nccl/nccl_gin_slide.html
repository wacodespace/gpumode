NCCL GIN

GIN：GPU 发起的内核内网络通信

CUDA 内核直接发起网络操作；NCCL 负责初始化、内存窗口管理和后端选择。

内容总结

  • GIN（GPU-Initiated Networking）允许 CUDA 内核中的线程直接发起网络通信（如 put / signal），无需返回主机端触发，从而消除 CPU 调度延迟。
  • 统一入口：内核通过 ncclGin::put 等 NCCL GIN API 发起操作，NCCL 在底层自动选择最优后端：
    • GDAKI — GPU 直接访问网卡（GPU Direct Async Kernel Initiated），绕过 CPU，延迟最低。
    • Proxy — GPU 将请求写入 CPU 队列，由 CPU 代理线程提交到 NIC；兼容性最广。
    • GPI — GPU 经 NIC 将工作卸载到 DPA（Data Path Accelerator，网卡上的可编程处理器），由 DPA 代替 CPU 执行网络操作。
  • 数据最终通过 NIC（IB / RoCE）发送到远程 GPU 的内存窗口（Window），完成 RDMA 写入。
  • 主机端仅负责一次性初始化：创建 communicator 并注册内存窗口，之后所有通信均在内核内完成。
  • 版本与环境要求：需要 NCCL 2.28.7 及以上版本，CUDA 12.2+ 以及 GIN context 支持。
  • 最佳应用场景：MoE（Mixture of Experts）和融合内核——这类场景中通信与计算交织，在内核内直接发起网络操作可以实现极细粒度的计算-通信重叠，避免同步屏障带来的空闲等待。
